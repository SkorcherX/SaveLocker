# v1.0.0

_Released 22 October 2026_

SaveLocker 1.0. Emulator saves are found and synced like any other game, a game can sync more than one folder, the server backs up your saves as well as its database, and two new safety checks stop a save from being lost by accident. Uploads are faster and can no longer publish a half-sent save.

## Before you upgrade

- **Back up `/data`.** This release changes the database (several migrations run the first time the new container starts), so going back to an older container afterwards isn't a clean rollback. The new server also takes a **Before upgrade** backup by itself before it migrates, but take your own copy too.
- **Keep `/data/keys` with the database.** The SteamGridDB key is now encrypted, and the key that decrypts it lives in `/data/keys`. It's created on first start, sits outside the database and is in no backup. If you move or restore the database somewhere without it, enter the SteamGridDB key again under Configuration. On unRAID, `/data/keys` is inside the appdata folder you already map to `/data`, so nothing changes as long as that folder persists.
- **Redeploy the console** (`docker compose pull && docker compose up -d`) **and update the agents.** Upload both packages (Windows and Linux) in **Config → Agent updates**: until you do, no agent is offered 1.0. Windows agents then prompt in the tray; Decks install the update at their next start.
- **The Decky plugin is unchanged** (v0.2.2).
- **Agents older than 1.0 keep working** against the 1.0 console. A game with more than one save folder syncs on them without losing anything, but they keep the extra folders inside the main one until they update, so update every machine that plays such a game.

## Emulator saves

**Add Games → Emulators** now lists one game per emulator save, found from the save files themselves, so it works however you launch the game (EmuDeck's ES-DE, Steam ROM Manager shortcuts, or the emulator's own menu). Each game syncs only its own files inside the folder every game of that emulator shares, together with its save states, and it never touches its neighbours' saves.

Supported: **RetroArch**, **melonDS**, **Supermodel**, **Model 2 Emulator**, **ScummVM**, **PCSX2**, **DuckStation**, **Dolphin**, **PrimeHack**, **PPSSPP**, **RPCS3**, **Vita3K**, **shadPS4**, **Cemu**, **Azahar** (and Citra's old folders) and **Xenia**. SaveLocker looks in EmuDeck's folders on SteamOS and Windows first, then in each emulator's own settings.

- **Games are named properly.** Disc games are named by their serial from Redump, 3DS games from No-Intro, Xbox 360 games by title ID, and PSN, Vita and PS4 games by the title inside the save. A console game's region is shown beside its name, and a USA and a European save are kept as two games, because each disc reads only its own region's saves.
- **Machines join by the save, not the name.** A Deck that names a ROM from EmuDeck's game list and a PC that has no game list still end up with one server game.
- **You can link a save by hand.** Each emulator row in Add Games says which server game it will join; **Change** lets you pick another, or keep the save as its own game.
- **Shared memory cards are never added as one game.** A card every game uses (PCSX2's card file, Dolphin's raw card, DuckStation's shared card) is listed greyed out, with how to switch the emulator to a card per game.
- **Filters:** an **Emulator** row and a **Console** row under the Emulators filter in the agent, and an **Emulators** filter in Game Mode.

Not in this release: **Nintendo Switch emulators**, and syncing Xenia's profile (gamertag, achievements) or DLC between machines.

Help: *Setting up emulator saves* and *Emulator backup best practices*.

## Several save folders per game

A game can now sync any number of folders: saves in both Documents and AppData, or an emulator's states beside its saves. When the save database knows another folder for a game:

- **Add Games** lists it under the game as **Also found**, ticked.
- For a game you already track, the agent's Overview shows **More save folders found**, with **Sync it**, **Don't sync** and **Not now**.
- The console's game page has an **Extra save folders** section to add or remove folders for every machine, and the CLI has `add-path` and `remove-path`.

A machine that doesn't have a folder still syncs the game, through a hidden copy, so the folder is never dropped from a save. Help: *Games with more than one save folder*.

## Save safety

- **An emptied save folder is held, not synced.** If every file in a game's save folder disappears at once (an uninstaller, a game's reset, the wrong folder cleared), the agent stops syncing that game on that machine and shows **Save files are gone**, with **Restore here** and **Delete everywhere**. Before, the empty folder would have been pushed and deleted the save on every other machine. The server also refuses an unforced empty upload over a save that has files. Help: *When every save file disappears*.
- **A pull keeps this machine's excluded files.** Files your exclude patterns leave out of the save are no longer removed when a pull replaces the folder.

## Backups of your saves, and encryption at rest

- **Backups now hold every game's latest save as well as the database**, as one zip. They run on a UTC daily or weekly schedule you set on the new **Backups** page, where you can also back up now, download, delete and restore.
- **Restore** checks the backup first and takes a **Before restore** backup, so a restore can be undone.
- **A Before upgrade backup** is taken automatically when the server starts on a new build, before any database migration.
- **The SteamGridDB key is encrypted** in the database (see *Before you upgrade* about `/data/keys`).

Help: *Backups and restoring*.

## Faster and safer uploads

- **Only changed files are uploaded.** For a larger save, the agent sends just the files that changed since the server's latest version, and the server rebuilds the version from them.
- **Large uploads are sent in chunks and are all-or-nothing.** An interrupted upload publishes nothing. Before, a retry in the middle of a chunk could publish a truncated save that other machines then pulled.

## Smaller improvements

- **Better save detection on Linux and the Steam Deck**, including Wine and Proton paths whose letter case differs from the save database's.
- **Conflicts show how the two sides differ**: file counts and each side's newest file time.
- **Duplicated Steam shortcuts are flagged.** When Steam has a game under several AppIDs (a launcher re-created its shortcut), Add Games and Game Mode say which AppID SaveLocker will follow.
- **Each machine records how it found a game** (*Emulator · RetroArch · SNES*, *Steam · Installed game*), shown under each machine on the console's game page and in the agent's tracked-games list.
- **The agent shows which build it's running**, not just its version, so a test build is easy to tell apart.
- **For the Decky plugin:** the agent now stores a per-game alias, a pull-before-launch override and whether a game has Steam Cloud, ready for a future plugin release.

## Security

- The console is now built with Node 22.23.4, and its container refreshes its CA certificates, following the distrust of a compromised eMudhra intermediate certificate.
